**The ordering is the result.**  Constant bias and per-image residual scatter
are both of order 1 sigma -- and 1.4-1.7 sigma on HRF.  The inter-observer
discrepancy (0.81 sigma on DRIVE, 1.35 sigma on CHASE_DB1) is the **same order
as the machine's own error**, i.e. the reference itself is not a point.  The
acquisition-perturbation spread is 0.35-0.56 sigma, a third to a half of the
error budget, and it needs no labels to observe (that is what E5 exploits).
The topology-specific component, **measured**, is 0.002-0.089 sigma -- one to two
orders of magnitude below everything else, which is the negative-control result
the pivot memo already assumed.

**Read the two topology columns as a bracket, not as a disagreement.**
`topology_extrap` is `mean H_net per sever event x mean n_should`: per event the harm is
0 (density, exactly) to 0.069 sigma (`results/pivot/e1_topology_detail.csv`, the ~10^-2 sigma of
the memo), but DRIVE/CHASE/HRF/FIVES carry 25.3 / 34.9 / 103.3 / 14.4
repairable events per image, so the additive extrapolation reaches 0.019-2.41
sigma (density excepted, where it is exactly 0). It is an upper bound that assumes (a) independence and additivity of
single-event harms and (b) that every break in the real prediction is like a
simulated severance of a GT mask. `topology_measured` is the empirical
counterpart on the same masks: repairing the events RiGR actually finds moves
the constant bias by 0.002-0.089 sigma. The truth is near the lower end --
RiGR-uniform accepts only 7.0-56.0 edges per image against `n_should` of
14.4-103.3, so part of the gap is unrepaired events, but `evapore_e2e`, which
accepts 113-734 edges per image, still only moves macro-MAE by 0.03-0.38
(`results/bias_diagnostics.md` section 2). The honest paper claim is the
**measured** number with the extrapolation quoted as the additivity-limit
bound.

### E1.5 Which component explains the attenuation

Three lines of evidence, in decreasing strength.

1. **The constant bias cannot, as a matter of algebra.**  A within-cohort
   classifier is invariant to a constant shift of a feature.  E6.2 below turns
   this into a run: applying the exact per-(dataset, biomarker) offset to every
   image reproduces the raw AUC to `abs diff = 0.0` in all six cells.  HRF's
   bias is the largest in the study (mean 1.70 sigma, up to 3.10 sigma on
   `total_length_pvbm`) and it buys **nothing** downstream.
2. **Topology cannot, by size.**  The measured topology component is
   0.006-0.068 sigma on HRF, 1-2 orders of magnitude below the residual
   scatter (mean 1.41 sigma).  `RESULTS_DIGEST.md` sections 2-3 independently
   found no reliability or utility effect from any repairer.
3. **Reliability is the only component that tracks the attenuation across the
   two labelled datasets.**  FIVES: non-tortuosity `r` 0.951, attenuation
   +0.004 [-0.016, +0.025].  HRF: `r` 0.435, attenuation +0.215 [+0.115,
   +0.321].  Same eight features, same classifier, same protocol; the constant
   bias is *larger* on the dataset that attenuates and the topology component is
   comparable, so `r` is the discriminating variable.

**Verdict: the flag works where the error is concentrated in a few catastrophic
images, and does nothing -- or harms -- where it is not.**

* **FIVES, macro: clear win.**  `r` 0.785 -> 0.846 (q = 10, p = 0.001) ->
  **0.869** (q = 20, p = 0.000) -> 0.862 (q = 30, p = 0.013), against a random
  mean that stays flat at 0.786-0.790.  The gain is almost entirely
  `tortuosity_skan` (0.071 -> 0.471) and `FD_pvbm` (0.842 -> 0.976); dropping
  20 % of images buys a 0.08 macro-`r` improvement no random drop reproduces.
* **FIVES, per-biomarker: decisive for the broken columns.**  `tortuosity_skan`
  0.071 -> **0.665** at q = 20 (p = 0.000, random mean 0.077);
  `FD_skan` 0.906 -> 0.967 (p = 0.001); `total_length_pvbm` 0.979 -> 0.990
  (p = 0.020).  For columns that are already at r > 0.98 (`density`,
  `total_length_skan`) gating is neutral-to-slightly-negative, as expected.
* **DRIVE, per-biomarker: the same pattern.**  `tortuosity_skan` 0.112 ->
  **0.744** at q = 20 (p = 0.015), `tortuosity_pvbm` 0.639 -> 0.759 (p = 0.037);
  every other column is a wash or worse.
* **HRF: negative.**  Macro `r` 0.512 -> 0.441 / 0.416 / 0.403 while random
  drops give 0.508 / 0.506 / 0.505, so `p_random_ge` = 0.92-0.93 -- **the flag
  is worse than dropping at random**.  Per biomarker, no column improves and
  five of eight have `p_random_ge > 0.8`.  Downstream AUC follows: 0.755 ->
  0.688 (q = 10, p = 0.995), 0.729 (q = 20, p = 0.645), 0.762 (q = 30,
  p = 0.315); the GT-oracle arm on the same retained sets falls 0.958 -> 0.940 /
  0.932 / 0.888, so part of the AUC movement is simply the loss of n.
  At n = 30 with 10 per class these CIs are enormous and nothing here is
  significant in either direction.

The honest summary for the paper: **cross-view dispersion is a usable per-image
unreliability flag for the biomarkers whose error distribution is heavy-tailed
(tortuosity everywhere, FD on FIVES), demonstrated on FIVES (n = 60) and DRIVE
(n = 20); it is not usable on HRF, and the HRF downstream gating experiment is
underpowered (n = 30) and negative.**  The FIVES n = 200 gating experiment the
proposal asks for needs one GPU inference pass over 8 views x 140 extra images
and should be re-run when a GPU frees up.

Framing that survives review: *per-domain recalibration with a few dozen
labelled images*, never *a universal calibrator*.

Why it is exact rather than approximate: logistic regression here is fitted on
standardised features, so a shift of a column changes only the intercept and
leaves every predicted probability identical; `HistGradientBoosting` splits on
order statistics, so a shift moves every candidate threshold by the same
constant and leaves the tree identical.  The residual differences that P2/P3's
`offset_per_ds` row showed (FIVES logreg 0.7135 vs `pred` 0.7134; HRF 0.727 vs
0.753) were produced by the **5-fold cross-fitting of the offset** -- different
folds get slightly different offsets, so the applied shift is not constant
across images -- not by the harmonisation.  That is worth saying explicitly in
the paper, because the HRF `offset_per_ds` row looks like "calibration hurts
AUC" and is actually "an offset estimated from 36 images is noisy".

**Conclusion for C3.**  Constant-offset harmonisation is a *reporting-scale*
tool: it makes biomarker values comparable across cohorts (60.7 % of the bias
removed in-domain, with honest 90 % intervals) and it is provably worth exactly
zero AUC inside a cohort.  Any claim that calibration improves clinical utility
is refuted by construction, not by an experiment that happened to come out flat.

## Known limitations

1. **No second observer for HRF or FIVES.**  The inter-observer reference scale
   exists only for DRIVE and CHASE_DB1, i.e. not for either of the two datasets
   that carry disease labels.  Any "machine error is within inter-observer
   error" claim is currently supported only on the unlabelled datasets.
2. **CHASE_DB1 test split is 8 images.**  Every CHASE_DB1 number in E1 and E6
   is effectively a point estimate.
3. **Seeds 1-2 come from the repair tables** and, for FIVES, from a 60-image
   subset; seed 0 is reported both ways so the gap is visible.
4. **The FIVES gating experiment runs on 60 view-covered images**, not the 200
   test images, and cannot report downstream AUC at all; the HRF AUC gating is
   n = 30 and underpowered.
5. **`H_net` uses the all-mask gateA sigma** while everything else uses the
   train-split sigma (ratio 0.94-1.05).
6. **The per-image attenuation regression is null** and is reported as such; the
   attenuation-vs-reliability claim rests on a two-dataset contrast, which is
   exactly why E3 of the proposal (external labelled cohorts) is load-bearing.
